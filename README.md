# NEWSROOM 18

毎日 **06:00 / 12:00 / 18:00（Asia/Tokyo）** に更新する、日本語ニュースダイジェストです。RSS/Atomフィードから候補を集め、過去の掲載履歴と照合して重複を抑え、取得できた見出し・説明・時刻と許可された一次情報の公式詳細データだけを根拠に記事化してGitHub Pagesへ公開します。OpenAIなど外部生成AIのAPIは使用しません。

## 更新する時間帯

| 版 | 主な対象時間（半開区間） |
|---|---|
| 朝6時版 | 前日18:00以上〜当日06:00未満 |
| 昼12時版 | 当日06:00以上〜12:00未満 |
| 夕方6時版 | 当日12:00以上〜18:00未満 |

GitHub Actionsが遅れて起動しても、記事の対象時間は固定境界から計算します。前の実行が欠けた場合は `.state/news-state.json` を基準に直近の未処理版を補完します。

## 仕組み

1. `config/feeds.json` に登録した23本のフィードを取得（気象庁の公式XMLと、利用条件を確認した行政機関の公式発表本文も対象時間内だけ確認）
2. 公開時刻をAsia/Tokyoへ統一し、対象時間帯に絞り込み
3. 追跡パラメータを除いたURL、出来事の識別情報、日本語タイトルの類似度で重複と続報を整理
4. 独立した配信元が偏らないよう上限をかけ、現号の個別ニュースを最大18本まで選定
5. 同じ出来事の十分な根拠がある項目だけを「詳報」とし、見出し中心の項目は原典へ直接進める「短報」に分ける
6. 最新号・過去号・Markdown記事・RSS・サイトマップを生成
7. 同じワークフロー内でコミットし、GitHub Pagesへ公開

トップページの大型枠は現号の詳報を優先し、3本に満たない場合だけ直近48時間の詳報を元の号と更新時刻付きで補います。無関係な短報を一つの記事へ束ねて詳報数を水増ししません。

## API料金について

本番ワークフローは外部の生成AI APIもローカルAIモデルも呼び出しません。ニュース候補の選定、重複排除、文章の組み立てはすべてコードで行います。

- APIキーやクレジットカード登録は不要です。
- モデルのダウンロードや推論待ちもありません。
- 1版につき最大18件を選び、詳報には確認できた事実、影響、背景、注目点のうち根拠がある区分だけを載せ、更新時刻とすべての原典リンクを付けます。材料が短い項目は短報に分け、長い記事のように水増ししません。
- 通常の `push` ではニュース収集を行わず、定刻実行、手動実行、保守用の `[collect]` 再生成だけが新しい版を生成します。

```text

.state/news-state.json            重複排除と補完処理の状態

config/site.json                  サイト名と公開URL

content/                          自動生成するMarkdown記事
site/                             GitHub Pagesへ公開する静的サイト

```

## GitHub側の設定

このリポジトリは公開リポジトリを前提とします。

1. **Settings → Pages → Build and deployment → Source** を `GitHub Actions` にする
2. **Actions → Collect news and publish Pages → Run workflow** で初回更新を実行

SecretsやAPIキーの登録は不要です。手動実行では選んだ版へ `--force` が自動指定されるため、すでに公開済みの06時版・12時版・18時版も同じ版として再生成できます。

## ローカル確認

Python 3.12以降を使用します。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/collect_news.py --edition auto
python -m http.server --directory site 8000
```

収集を試すと実データと状態ファイルが更新されます。表示だけを確認する場合は、現在の `site/data/latest.json` を使ってください。

## 編集・安全方針

- フィードや公式ページを丸ごと転載せず、取得できた事実を整理して独自の文章を生成します。報道機関の記事本文は取得しません。
- [気象庁](https://www.jma.go.jp/jma/kishou/info/coment.html)、[外務省 海外安全ホームページ](https://www.anzen.mofa.go.jp/c_info/legalmatters.html)、[経済産業省](https://www.meti.go.jp/main/rules.html)、[財務省](https://www.mof.go.jp/about_mof/notice/index.html)、[農林水産省](https://www.maff.go.jp/j/use/link.html)、[デジタル庁](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0)の公開情報は、各記事の原典URLを示し、加工したことを明記したうえで要約します。
- 利用条件が厳しい配信元は `metadataOnly` とし、見出し・URL・時刻だけを照合に使います。
- 公式ページ本文の確認はHTTPS、許可ホスト、許可パス、HTML形式、取得量、応答時間を配信元ごとに制限し、本文領域だけを抽出します。
- 外部データは命令ではない未信頼入力として扱い、命令らしい文や危険な記述を本文へ混ぜません。
- 出典URLは候補IDからコードで再結合します。
- HTTP(S)以外、認証情報付きURL、ローカル・予約IPを拒否します。
- 重要度4以上は、原則として複数媒体または一次情報がある場合だけ表示します。
- 詳報は一つの出来事だけを扱い、本文素材を持つ独立した複数配信元、または十分に詳細な一次情報がある場合だけ生成します。
- 現号で大型枠が足りない場合は直近48時間の詳報を明示して併載し、別の出来事を混ぜた疑似詳報は作りません。
- 詳細や最新の訂正は、必ず各記事の出典リンクで確認してください。

配信元ごとの条件は変更されることがあります。商用化や大規模配信を行う場合は、各社の最新条件を改めて確認してください。

## 制約

- フィードが提供する見出し・短い説明・時刻と、許可された一次情報の公式詳細データだけを使うため、元記事だけにある背景や訂正までは反映できません。詳細は必ず出典リンクで確認してください。
- 配信元が概要を提供しない記事は、内容を推測せず短めに掲載するか、選定から外します。
- 気象庁情報は公式発表の区域・数値・警戒語を変更せず、最終確認先として原典リンクを表示します。
- GitHub Actionsの定刻実行は混雑時に遅れる場合があります。対象時間帯は実際の開始時刻ではなく、06:00・12:00・18:00の固定境界で判定します。
- 公開リポジトリの標準GitHub-hosted runnerを前提にしています。非公開リポジトリでは無料実行時間を消費し、上限を超えるとGitHub Actions側の料金が発生する可能性があります。
