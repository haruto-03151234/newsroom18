# NEWSROOM 18

毎日 **06:00 / 12:00 / 18:00（Asia/Tokyo）** に更新する、日本語ニュースダイジェストです。RSS/Atomフィードから候補を集め、過去の掲載履歴と照合して重複を抑え、ローカルAIで記事化して静的なGitHub Pagesサイトとして公開します。外部AIのAPIキーも、従量課金契約も必要ありません。

## 更新する時間帯

| 版 | 主な対象時間（半開区間） |
|---|---|
| 朝6時版 | 前日18:00以上〜当日06:00未満 |
| 昼12時版 | 当日06:00以上〜12:00未満 |
| 夕方6時版 | 当日12:00以上〜18:00未満 |

GitHub Actionsが遅れて起動しても、記事の対象時間は固定境界から計算します。前の実行が欠けた場合は `.state/news-state.json` を基準に直近の未処理版を補完します。

## 仕組み

1. `config/feeds.json` に登録した15本のフィードを取得
2. 公開時刻をAsia/Tokyoへ統一し、対象時間帯に絞り込み
3. 追跡パラメータを除いたURLと日本語タイトル類似度で重複を排除
4. GitHub Actions内のQwen3-4Bと根拠ベースの編集を組み合わせ、重要度の高い通常6〜7本を日本語記事へ編集
5. ローカルモデルが失敗した場合も、出典を明記した決定論的フォールバックで継続
6. 最新号・過去号・Markdown記事・RSS・サイトマップを生成
7. 同じワークフロー内でコミットし、GitHub Pagesへ公開

## ローカルAIについて

記事編集には、Apache 2.0で公開されている **Qwen3-4B-Q4_K_M（GGUF）** と、固定版の **llama.cpp b10437** を使います。どちらもGitHub Actionsの標準Linuxランナー内で動作し、ニュース候補を外部の生成AI APIへ送りません。

- APIキーやクレジットカード登録は不要です。
- 初回実行では約2.5GBのモデルを取得します。SHA-256を検証した後、GitHub Actionsのキャッシュへ保存します。
- キャッシュが残っている通常回はモデルの再取得を省略します。キャッシュが失効・削除された場合は再取得します。
- 1版につき、通常6〜7件を選びます。各記事には要約だけでなく、重要な理由、分類、更新時刻、根拠となる出典リンクを付けます。
- 通常の `push` ではニュース収集もモデル取得も行わず、テストと既存サイトの公開だけを行います。定刻実行、手動実行、保守用の `[collect]` 再生成だけが新しい版を生成します。

## GitHub側の設定

このリポジトリは公開リポジトリを前提とします。

1. **Settings → Pages → Build and deployment → Source** を `GitHub Actions` にする
2. **Actions → Collect news and publish Pages → Run workflow** で初回更新を実行

SecretsやAPIキーの登録は不要です。手動実行では選んだ版へ `--force` が自動指定されるため、すでに公開済みの06時版・12時版・18時版も同じ版として再生成できます。

## ローカル確認

Python 3.12以降を使用します。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/collect_news.py --edition auto
python -m http.server --directory site 8000
```

収集を試すと実データと状態ファイルが更新されます。表示だけを確認する場合は、同梱の明示的なサンプルデータを使用してください。

## 編集・安全方針

- フィード本文や画像を転載せず、短い候補情報から独自の文章を生成します。
- 利用条件が厳しい配信元は `metadataOnly` とし、見出し・URL・時刻だけを照合に使います。
- 外部データは命令ではない未信頼入力として扱い、モデルにツールや秘密情報を渡しません。
- 出典URLはモデルに生成させず、候補IDからコードで再結合します。
- HTTP(S)以外、認証情報付きURL、ローカル・予約IPを拒否します。
- 重要度4以上は、原則として複数媒体または一次情報がある場合だけ表示します。
- 詳細や最新の訂正は、必ず各記事の出典リンクで確認してください。

配信元ごとの条件は変更されることがあります。商用化や大規模配信を行う場合は、各社の最新条件を改めて確認してください。

## 制約

- Qwen3-4Bは4B規模の量子化モデルです。大規模なクラウドモデルほど文章力や判断精度は高くなく、誤訳、重要度の取り違え、不自然な表現、根拠のない補完が起こり得ます。
- モデルには記事本文ではなく、フィードが提供する見出し・短い説明・時刻などを渡します。そのため、元記事だけにある背景や訂正までは反映できません。詳細は必ず出典リンクで確認してください。
- GPUを使わないCPU推論のため、候補数や混雑状況によって更新に時間がかかります。ワークフローは安全のため45分で終了します。
- GitHub Actionsの定刻実行は混雑時に遅れる場合があります。対象時間帯は実際の開始時刻ではなく、06:00・12:00・18:00の固定境界で判定します。
- 公開リポジトリの標準GitHub-hosted runnerを前提にしています。非公開リポジトリでは無料実行時間を消費し、上限を超えるとGitHub Actions側の料金が発生する可能性があります。
- モデルのキャッシュは恒久保存ではありません。失効時には約2.5GBを再ダウンロードするため、その回は通常より長くかかります。
